### Phase 1 (in progress)

- **feat(plan): the agent returns a structured full-funnel plan, and the card renders it.** A vertical slice through all five layers, closing the largest remaining piece of the Phase 1 gate. A new `grounded-plan-v1` core returns six fixed funnel stages with up to three steps each, every step carrying an owner (AI / HUMAN / YOU) and the source indices it rests on; `packages/contracts` owns the wire shape so Python, Fastify and the browser derive from one definition; a new `action_embeds` table (`20260812120000`) persists it; and `PlanCard.tsx`, kept unwired since the mock era, now renders real data. **The plan is validated, not trusted:** `parse_plan` normalises the six stages into fixed order (the model omits and reorders them, and a card silently showing four reads as "the plan has four parts" rather than "two stages had no sources"), range-checks citation indices (a step citing `[7]` against six sources is a reference the reader cannot follow), and rejects an all-empty plan, since six empty stages is a refusal wearing a card's clothing. A model that cannot produce a valid plan falls back to cited prose, degrading **sideways rather than down**, and never to an ungrounded plan. Two things were deliberately removed rather than filled in: the card's estimated cost and timeline, which were mock leftovers and would have been invented figures on the one surface whose purpose is to be checkable; and the approve buttons, which stay absent until the action route exists, because a button that does nothing is worse than a missing one. Empty stages render as empty on purpose. 69 Python tests (10 new), typecheck 4/4, build green.

- **fix(db): revoke default privileges that RLS cannot protect against.** Found while verifying the grants on the new `action_embeds` table: Supabase's default privileges had granted `REFERENCES, TRIGGER, TRUNCATE` to **anon** on every table in `public`, and `TRUNCATE` to `authenticated`. RLS filters rows a grant already permits, but **`TRUNCATE` is not row-level and bypasses policies entirely**, so a role holding it can empty a table whatever the policies say. `anon` held it on `messages`, `rooms` and the whole RAG corpus, flatly contradicting `20260728170000`'s "anon gets nothing. No unauthenticated surface exists in chat." Honestly scoped: **not remotely exploitable**, since PostgREST exposes no `TRUNCATE` verb, so there was no route to it through the API; closed because a privilege that cannot be justified should not be held. `anon` now has nothing at all and `authenticated` has exactly `SELECT` (plus `INSERT` on messages, `UPDATE` on profiles), verified against the live database. The durable half is an `alter default privileges`, without which the cleanup decays the next time anyone adds a table.

- **fix(ai): a rate limit is not a transient 5xx.** The first armed CI eval run failed, and the log showed why twice over. `_post_with_retry` treated `429` exactly like a `503`, retrying after 0.5s and 1.0s; a provider quota is quoted **per minute**, so those retries cannot succeed and each one spends another call against the same exhausted quota, making failure certain rather than recovering from it. `429` now backs off on a minute scale (`Retry-After` when the provider sends one, else a 20s floor), while 5xx keeps its fast curve so a blip does not become a timeout inside the agent step. The floor is deliberately not a full minute: this runs inside a bounded agent step, and waiting out the whole window trades a fast failure for a slow one. Separately, CI's eval pacing went from 7s (≈8.5 calls/min, close enough to the 10/min trial cap that it tripped partway through the set) to 10s. 59 Python tests (6 new), sleeps captured rather than performed so the suite asserts the schedule without waiting for it. **The real fix remains a production Cohere key**, which the same cap will otherwise impose on live traffic.

- **feat(rag): retrieval eval gate on a versioned golden set.** `services/ai/eval/golden.json` (14 cases) plus `python -m octopus_ai.evaluation`, which runs the real pipeline and exits non-zero on a regression. Scores two halves **asymmetrically on purpose**: positives must surface the expected document (recall ≥ 0.80), negatives must return **nothing at all** (zero tolerance). A miss makes the agent refuse an answerable question, which is unhelpful but safe; a leak hands the planner loosely-related text that it then grounds a confident cited answer in, so one leak fails the run. Kept as a file rather than `eval_golden_set` rows because document UUIDs are generated per ingest and cannot travel between laptop, CI and production; queries are phrased as a founder would ask, since a set echoing the corpus measures string matching. **Baseline: positive recall 1.00, MRR 1.00, zero leaks**, with true positives scoring 0.127–0.637 while out-of-scope queries do not reach 0.05 at all. That result **disproved a suspicion rather than confirming one**: "0 below threshold" had been read on in-scope queries as the threshold having stopped filtering, when dropping nothing on a covered question is correct behaviour. `rerank_min_score` needed no recalibration after the corpus tripled and the embedder changed. Generation metrics (Ragas/DeepEval faithfulness, answer relevancy) are deliberately excluded: they need an LLM judge, which costs money per run and is non-deterministic, so they belong in a separate credentialed pass rather than in a gate. Also found by running it: **the Cohere key is a trial key limited to 10 calls/minute**, which the set exceeds outright and which will equally throttle production once a user asks more than ten questions in a minute; `EVAL_CASE_DELAY_S` paces the harness without slowing production retrieval. Wired into CI as its own job that **cannot gate until repository secrets exist** and says so with a warning rather than reporting a green check that measured nothing. 53 Python tests (8 new), no network. Updated `rag-knowledge.md`, `ai-orchestrator.md`, `DEVELOPMENT.md`, `ci.yml`.

- **fix(ai): warm the local embedder at startup, and stop the refusal message understating the corpus.** Three defects found by running the app rather than by reading it. (1) A live agent run failed with "the reasoning service did not respond" while the service was healthy and answering `/health`: bge-m3 was loading inside the first request, and the several seconds of model load pushed a normal turn past Node's 30s `requestPlan` budget. The model is now loaded during FastAPI startup, where nothing is waiting on it and where a missing or corrupt model fails with a named error instead of surfacing on a user's first question. (2) The budget rose to 90s, since a CPU embed is work rather than an API call; the warm-up means it covers steady-state work, not a cold load. (3) The refusal message hardcoded the original four corpus topics, so after the corpus grew to ten documents the agent advertised a narrower knowledge base than it had, and a user whose question _was_ covered would be told it was not and would not retry. The enumeration is gone: it drifts on every corpus change and fails in one direction only. The message now describes the domain, which is fixed by the first vertical rather than by document count. Updated `architecture.md` and `ai-orchestrator.md`. Also corrected two silent errors in `DEVELOPMENT.md`'s uv PATH snippet: it named a directory that holds no `uv` on Python 3.13 (so PATH looked configured and the command still failed), and it wrote the merged `$env:Path` into the _User_ scope, permanently copying every machine entry into the user's PATH on each run.

- **feat(rag): six seed-corpus playbooks covering the empty funnel stages.** The corpus held four documents against a sixteen-step funnel playbook, and all four sat in the _channels_ stage: strategy, content, creative and conversion had no sources at all. Because the rerank threshold drops weak chunks, that is not a quality gap but a **refusal** gap, since a goal with nothing in scope degrades to `refusing-v0` by design. Adds `positioning-icp`, `offer-design`, `content-strategy`, `creative-direction`, `landing-conversion` and `organic-social`, taking the corpus to ten documents and 43 in-force chunks. Written as principles and diagnostics rather than platform specifics (character limits, ad formats, fee levels), because those go stale between crawls and rag.md forbids quoting them from memory; volatile facts belong in crawled, effective-dated sources or typed rows. Kept `authority: internal` and attributed to nothing external, per the standing rule that an invented citation is worse than none. Verified: re-running the seed skipped all four existing documents on an unchanged hash and wrote only the 30 new chunks, confirming change detection does not re-embed needlessly. Measurement remains the one uncovered stage and is recorded as such in `rag-knowledge.md` and `ai-orchestrator.md`.

- **feat(rag): local BGE-M3 embeddings, selectable per environment** ([ADR-0008](docs/40-adr/0008-local-bge-m3-embeddings.md)). `EMBED_PROVIDER=local` runs `BAAI/bge-m3` in-process via FlagEmbedding instead of calling OpenAI, so no corpus text leaves the machine. Default stays `openai`. bge-m3 is natively 1024-dim (verified against the model config, then confirmed empirically: 1024 dims, norm 1.000000), so `halfvec(1024)` and the HNSW index are **unchanged**. torch ships as the optional `local-embed` extra and the module is imported lazily, so CI and OpenAI-backed deploys never install it. **The load-bearing fix is to `content_hash`:** it previously covered only `CHUNKER_VERSION` and the text, so switching embedder would have left every document "unchanged", keeping old vectors while new rows claimed the new model and comparing query vectors against a foreign vector space in the same index, silently and without error. It now folds in the active embedding model, so a switch self-invalidates. Also found by running it: excluding the repo's unused 2.3 GB ONNX duplicate breaks `HF_HUB_OFFLINE` loading, because FlagEmbedding re-resolves the repo id without those exclusions and judges the cache incomplete; loading from a snapshot path bypasses it, which is what a container wants anyway. Taken on **data-residency** grounds (the flywheel will ingest customer outcome data) and on timing (four documents makes the re-embed free now, not later); retrieval quality vs OpenAI is **unmeasured** until the eval gate exists, and is recorded as such. Model **identity** (`EMBED_LOCAL_MODEL`, recorded and hashed) is kept separate from model **location** (`EMBED_LOCAL_PATH`, host-specific), because collapsing them writes a laptop's cache path into every row's provenance and makes an identical model on a differently-laid-out server look like a change worth re-embedding. **Now live:** the seed corpus is re-embedded on bge-m3, 13 chunks across 4 documents, with the previous OpenAI-embedded versions superseded rather than deleted. `hybrid_search` filters on `valid_from`/`valid_to`, so the two vector spaces coexist in `doc_chunks` for audit but never meet in a query, verified against the database. Retrieval probe on "how do I lower my CPA on paid social" returned 4 chunks, all from the correct document, top score 0.644. 45 Python tests (10 new), no network. Updated `ai-orchestrator.md`, `rag.md`, `rag-knowledge.md`, `tech-stack.md`, `integrations.md`, `DEVELOPMENT.md`, `.env.example`.

- **docs: correct four code comments that misstated the session as `httpOnly`.** `lib/supabase/server.ts`, `lib/api-client.ts`, `app/api/bff/[...path]/route.ts` and `app/sign-in/page.tsx` each asserted the session cookies were `httpOnly` and the access token therefore unreachable by page scripts. Two of them cited `auth-identity.md`, which says the opposite: the cookies are deliberately **not** `httpOnly` because `@supabase/ssr`'s browser client must read them to authenticate the Realtime socket. The comments were claiming a security property the system does not have, which is worse than silence on a trust surface. Replaced with the real rationale for the BFF (token attached server-side in one place, browser never holds a long-lived credential for Fastify, API origin unexposed). Also refreshed `apps/README.md`, `packages/README.md` and `supabase/README.md`, which still read "No code yet" and listed a `packages/rag` that ADR-0006 superseded before it existed. No behaviour change.

- **fix(web): `/app` declares `force-dynamic`, unbreaking CI's `next build`.** The workspace route became dynamic only as a side effect of `await cookies()` raising Next's dynamic-usage bailout. `createClient()` validates the Supabase env first, so in an environment with no env, it threw an ordinary error before the bailout was ever raised and `next build` failed prerendering a route that is per-request by definition. Local builds passed throughout on the strength of a present `.env.local`, which is precisely what hid it. Fixed by declaring the route dynamic instead of inferring it; CI keeps building with **no** Supabase env, since a build that needs runtime config to compile is the actual defect. Reproduced locally with the env cleared, then verified green: typecheck 4/4, prettier clean, build successful with `/app` reported as `ƒ (Dynamic)`. Updated `design-system-frontend.md`.

- **RAG is live: the agent now answers from a cited corpus, or refuses.** New migrations `20260728210000_rag_schema.sql` (`knowledge_sources` / `documents` / `doc_chunks` / `eval_golden_set`, `halfvec(1024)` + HNSW + generated per-language `tsvector`, RLS **and** grants in the same migration) and `20260728220000_hybrid_search.sql` (dense + sparse fused by RRF k=60 in one SQL query). `services/ai` gains ingestion (structure-first chunking, batched embedding, content-hash supersession), retrieval (OpenAI embed → `hybrid_search` → Cohere `rerank-v3.5` → relevance threshold), and a `grounded-v1` planner that cites sources by document title. Nothing above threshold, or any retrieval/generation failure, degrades to `refusing-v0` rather than to an ungrounded answer. Seed corpus of four internally-authored documents in `services/ai/corpus/`. 35 Python tests, no credentials required. Verified end to end: a CPA question returns a cited plan drawn from the corpus; "get a liquor licence in Tbilisi" is refused, not invented. Four bugs found by running it: RRF returned `numeric` against a `double precision` signature, whitespace-only documents produced an empty chunk, a bare heading was stranded as a 3-character chunk, and re-ingestion created duplicate live documents instead of superseding. Rerank threshold calibrated from measured score bands, not guessed. Model IDs and the `max_completion_tokens` parameter shape verified against the API (rule 21).

- **The agent is a chat member: Node/Python seam live end to end** ([ADR-0006](docs/40-adr/0006-python-ai-service-node-backend.md)). New `services/ai` (FastAPI + Pydantic, uv + ruff + pytest, 10 tests) exposing `GET /health` and `POST /plan`, which returns typed **proposals**. New `POST /api/rooms/:roomId/agent-runs` in `apps/api` returns `202 + runId`, calls the reasoning core, and executes proposals by posting as `author_kind='agent'` with a deterministic idempotency key. Sending a message in `apps/web` now starts a run and the reply arrives over Realtime. Parallel `ai` CI job (ruff + pytest); the eval gate waits for RAG. The core is `deterministic-v0` and **calls no model**: it acknowledges the goal and declines to plan ungrounded, reporting `grounded: false`, because uncited output cannot gate action (rule 10). The boundary is structural, not conventional: `services/ai` holds no database client at all, Node parses every response against a schema and honours only proposal kinds it knows, and a failed run posts a system message rather than going quiet. **Not durable yet** (in-process; Trigger.dev needs credentials). Verified with 11 API assertions plus a Realtime probe confirming broadcast to a subscribed member.

- **Chat shell runs on live data; all mock and demo content removed.** Deleted `apps/web/lib/mock.ts` (the seeded "Maya / Rune" conversation, fabricated plan, fake agent auto-reply, hardcoded budget and unread counts). Added Supabase sign-in/sign-up at `/sign-in` with middleware session refresh and route gating, a thin BFF at `/api/bff/*` that attaches the token server-side, and `GET|POST /api/rooms` + `GET /api/rooms/:roomId/{channels,members}`. The stream, composer, member panel and ⌘K palette now read real rooms, channels, profiles, message history, Realtime delivery and Realtime Presence; sends are optimistic and reconciled on the server copy, keyed by a client `idempotencyKey`. Surfaces with no backend (plan card, agent replies, budget) are **not rendered** rather than faked; `PlanCard.tsx` is kept unwired for Phase 2. Two migrations were needed and both were found by testing in a browser: `20260728190000` (own-row-only profile RLS made the member list impossible) and `20260728200000` (`channel.track()` needs an INSERT policy on `realtime.messages`, without which every member silently shows offline). Also corrected a doc-vs-reality error: the session cookies are **not** `httpOnly`, since `@supabase/ssr`'s browser client must read them to authenticate Realtime.

- **Server-authoritative chat write path** (`apps/api`). `POST /api/rooms/:roomId/messages` (JWKS preHandler → RLS membership → insert → Postgres trigger broadcasts) and `GET /api/rooms/:roomId/messages` (since-cursor catch-up), typed from `packages/contracts`. Routes act on Postgres as the _caller_ (publishable key + the caller's token) so RLS is the real backstop; the secret key stays reserved for trusted no-user-context writes. `authorId`/`authorKind` come from the JWT, never the body; `idempotencyKey` replay returns the original message. Verified end-to-end against Supabase, 24 assertions plus confirmed Realtime delivery to a live subscriber. Two bugs found by that verification and fixed: `20260728170000_grant_table_privileges.sql` (both prior migrations shipped RLS policies with **no** table grants, making every table unreachable) and `--env-file-if-exists` in the api scripts (nothing was loading `apps/api/.env`).

- **Chat schema live on Supabase.** Applied `20260728120000_chat.sql` (rooms/channels/room_members/messages, membership RLS via a `SECURITY DEFINER` helper, `realtime.broadcast_changes()` insert trigger, Realtime subscribe policy) and `20260728160000_harden_security_definer.sql`, which moves the policy helper into a non-exposed `private` schema and drops the default PUBLIC execute grant on the trigger functions — clearing all 8 Supabase security-advisor lints. Updated `data-model.md`.

### Changed

- **Decision: OpenAI for generation + embeddings; Cohere retained for rerank** ([ADR-0007](docs/40-adr/0007-openai-generation-embeddings-cohere-rerank.md)). Replaces the Voyage + Anthropic pins. Embeddings become `text-embedding-3-large` requested at `dimensions: 1024`, so **`halfvec(1024)` and the HNSW index are unchanged**. Rerank stays on Cohere `rerank-3.5` because OpenAI has no reranking endpoint and rerank is where retrieval precision is won. Taken while the corpus is still empty, since one embedding model must cover the whole corpus. Open risk recorded: `text-embedding-3-large` is weaker than Voyage on lower-resource languages, so the deferred Georgian/Russian pack's retrieval quality must be measured at the eval gate rather than assumed. Env keys become `OPENAI_API_KEY` + `COHERE_API_KEY`. Updated `README.md`, `tech-stack.md`, `rag.md`, `rag-knowledge.md`, `integrations.md`, `.env.example`.

- **Decision: Python AI service + Node/Fastify backend** ([ADR-0006](docs/40-adr/0006-python-ai-service-node-backend.md)). The AI/RAG layer (ingestion, retrieval, agent reasoning, eval, models) runs as a separate Python service (FastAPI + LlamaIndex); Node/Fastify keeps chat/auth/marketplace/payments + the durable backbone + all side-effecting tools. _Python proposes, Node executes._ Updated `README.md`, `architecture.md`, `rag.md`, `tech-stack.md`, `ai-orchestrator.md`, `rag-knowledge.md`, `infra-devops.md`, `.docmeta.yml`.
- **Strategy: wedge-first go-to-market.** First shipped vertical is now **full-funnel digital marketing for solo founders/creators**; business-formation (the cafe story, incl. Georgia/Tbilisi) becomes a later expansion vertical (north star unchanged). Introduced the **learning flywheel** as the moat — ingest campaigns+outcomes · human-node feedback as labeled data · auto-optimize on live metrics · fine-tune a proprietary model later.
