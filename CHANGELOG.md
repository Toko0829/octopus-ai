  **The model never proposes the budget, and that is the decision the card is built around** ([ADR-0011](docs/40-adr/0011-spend-cap-checked-twice.md)). `ProposeCampaignProposal` has no budget field on either side of the wire, the drafting path strips budget-shaped keys before validation, and the payload mapper sets `budgetCap: null` with no parameter for it. Both halves are pinned to the same boundary by two suites, so drift fails a test rather than passing quietly.
  **A live gap of the class already recorded twice here closed with it:** `projects.budget_ceiling` had existed since `20260813120000` with **no reader and no writer anywhere in TypeScript**, so `checkSpendCap` composed a number nothing could set and would have refused every campaign forever with `no_ceiling_authorised`. `PATCH /api/projects/:projectId` is owner-only, audited as `project.budget_set` with an explicit `actor_id` because the `auth.uid()` idiom reads null under the service key, and the panel shows authorised, committed and available using the same two filters the approval applies.

That is the NULL twin of the `NaN` case `spend.ts` already guards, and both are the same thing: not an error, not a type mismatch, a wrong answer wearing the shape of a right one.

- **feat(artifacts): `storage_path` has existed for two weeks and nothing could ever put anything in it.** The column landed with `20260813160000`, `Artifact.storagePath` went on the wire, `projects.ts` selected it, and the project panel had an arm reading "This one is a file rather than text." There was **no bucket, no policy, no reader and no writer**, so that sentence described a state the product could not produce and the arm was reachable only by a row nobody could create. The premise correction is worth keeping: this was never a missing column, it was a missing everything-else.
  **A private bucket, and the path convention is the tenancy scheme**: `<project_id>/<artifact_id>/<filename>`. The first segment is the tenant and the `storage.objects` select policy reads it, so a file written anywhere else in the bucket is visible to nobody, which is the safe direction for a convention to fail in. `writeFileArtifact` builds it through one function that strips separators and traversal out of the filename, because that name arrives from an artifact title or a provider response and a `../` in it would move the object out of its tenant folder or into somebody else's.
  **The tenant is parsed by a `private` function rather than by an inline cast, and that is a real failure mode.** `((storage.foldername(name))[1])::uuid` raises on any object whose first segment is not a UUID, and Postgres does not promise to evaluate the `bucket_id` test first, so **one stray object anywhere in Storage could have turned every member's listing into an error** rather than a shorter list. `private.artifact_object_project` returns null instead, and null is nobody. The pgTAP suite keeps a junk-path object in the bucket while a member counts rows, so the assertion is the absence of an error.
  **The route reads the artifact row as the caller, and that read is the authorization.** If `artifacts_select_member` does not return the row there is nothing to sign; the service key appears only afterwards, to mint the URL. Default stays `openai`. bge-m3 is natively 1024-dim (verified against the model config, then confirmed empirically: 1024 dims, norm 1.000000), so `halfvec(1024)` and the HNSW index are **unchanged**. torch ships as the optional `local-embed` extra and the module is imported lazily, so CI and OpenAI-backed deploys never install it. **The load-bearing fix is to `content_hash`:** it previously covered only `CHUNKER_VERSION` and the text, so switching embedder would have left every document "unchanged", keeping old vectors while new rows claimed the new model and comparing query vectors against a foreign vector space in the same index, silently and without error.
